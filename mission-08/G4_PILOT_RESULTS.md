### 2.3 读法

1. **紧凑规则单独远不如记忆**（Gate 3），**但与记忆组合时提供了记忆之外的信息**：成年个体上对数似然 +0.008 比特 / 对（区间不含 0），AUROC 从 0.85 升到 0.90–0.91，AUPRC 从 0.63–0.64 升到 0.68–0.69。只有密度的 ER 先验没有这种效果。
2. **信息来自类型块，而不是发育成分**：块模型（Cook 13 类或推断 8 类）与三时期 R1 的效果相同；只用独立特征的 K1 作为先验时效果小得多。
3. **在发育目标上，对数似然的增益大部分来自密度校准**（ER 先验就能得到），排序的增益来自类型块（AUROC 0.85 → 0.92–0.94）。因此 S-c 的参照改为 C(记忆, ER)（修正案 A2.1），只有类型块带来的部分才能通过。
4. 机制上，这是已知的统计做法：以块模型为先验对一个个体的连接做收缩（经验贝叶斯）。它支持的命题是"紧凑的类型级规则携带单个个体的连接表所没有的跨个体信息"，不是"发现了新的发育规律"。

## 3. 冻结的候选与基线

- **K2**（修订 1）= C(X)，X = B3：成年 C(M4, B3)，发育 C(M2, B3 的年龄内插版本)。B3 的类型数按 §4 的选择为 16（上表与 §2 的试验用的是 8）。
- **K1** 不进入确认，作为基线报告。
- 预注册的 R1（主规则见修正案 A3.1）与全部基线照常进入确认。
- 线虫功能线与果蝇 T4 线没有候选开发（修正案 A1.5；T4 的预测在 Gate 3 已写定）。
- 路线 C（构造）没有候选：没有可用的功能约束。

## 4. 冻结前补做的超参数选择（修正案 A4.1，`results/g4/selection.json`）

冻结前核对判决代码时发现，§2.2 规定在开发代理任务上选择的四个超参数从未选择。选择规则在运行之前写入修正案 A4.1；主指标是每对平均对数似然增益（相对 B0）。

| 超参数 | 网格 | 代理任务上的平均对数似然增益（比特 / 对） | 选出 |
|---|---|---|---|
| B3 的类型数 k | 4 / 8 / 16 | 0.0325 / 0.0497 / **0.0696** | **16**（AUROC 0.82–0.84，AUPRC 0.32；k = 8 为 0.78–0.79 与 0.22） |
| M1 的平滑 α | 0.01 / 0.02 / 0.05 / 0.1 / 0.2 | 0.043 / 0.069 / **0.082** / 0.061 / 0.000 | 0.05（未变） |
| M2 的平滑 α（留一阶段 W3、W5、W6） | 同上 | **0.115** / 0.114 / 0.092 / 0.048 / −0.033 | **0.01**（原来用 0.05） |
| B4 的 L2 强度 C | 0.01 / 0.1 / 1 / 10 | 0.0125 / 0.0137 / 0.0142 / **0.0142** | 10（与 1 只差 0.0001） |
| R1 的互惠 γ（Cook 13 类） | 1 / 3 / 7 / 15 | **0.0338** / 0.0337 / 0.0337 / 0.0337 | **1**（无互惠） |

读法：

1. **k = 16 落在预注册网格的边界上**，更多的类型可能更好；网格按预注册不扩大。K2（= C(记忆, B3)）随之使用 16 个类型（修正案 A4.1）。以 k = 16 的 B3 为参照，K1 的对数似然增益只有它的约 28 %（k = 8 时为 39 %，K1 的失败线按事先写下的 k = 8 判定，不重新判定）。
2. **M2 的平滑从 0.05 降到 0.01，记忆基线在发育目标上变强**（三个代理任务的平均增益从 0.092 升到 0.115 比特 / 对）。这使 S-d（多时期规则 > M2）更难成立；S-c 的参照 C(M2, ER) 本身会重新校准，受影响较小。
3. **互惠 γ 不改善单边预测**：γ 从 1 增到 15，代理任务上的对数似然增益从 0.0338 降到 0.0337，AUROC 不变（0.776–0.778）。γ 显著改变二元组统计：模型的互惠比例从 0.07（γ = 1）升到 0.15、0.23–0.24、0.30–0.32（γ = 3、7、15），观测为 0.27（W7）与 0.31（W8），即密度² 的 76 与 86 倍。这与论文的说法一致：互惠参数改善三元组分布，而"不改变预测单个突触的 AUROC"。按规则取 γ = 1；互惠的错配在 Gate 5 的次要分析中报告（修正案 A4.3）。论文选 γ = 7 是为匹配互惠（用 8 个推断类型），我们在 Cook 13 类上看到与观测最接近的是 γ = 15。
4. **选出的值下 K2 的开发表现**（`results/g4/ablation_selected.json`，k = 16、M2 的 α = 0.01；与 §2 同样的拟合—评分方向）：

   | 代理任务 | 记忆 | C(记忆, ER) | C(记忆, B3)，k = 16 | 与记忆之差 [95 % 区间] | AUROC / AUPRC |
   |---|---|---|---|---|---|
   | 成年，评分 W7 | M4 +0.142 | +0.142 | +0.152 | +0.0098 [+0.0071, +0.0124] | 0.913 / 0.684 |
   | 成年，评分 W8 | M4 +0.147 | +0.146 | +0.158 | +0.0115 [+0.0092, +0.0140] | 0.919 / 0.698 |
   | 发育，评分 W5 | M2 +0.117 | +0.114 | +0.126 | — | 0.933 / 0.686 |
   | 发育，评分 W1 | M2 +0.012 | +0.060 | +0.073 | — | 0.949 / 0.530 |

   与 k = 8 相比，成年上的增益略大（+0.008 → +0.010–0.012），发育目标上相对 C(M2, ER) 的增益约 +0.013 比特 / 对。
5. 二元组实现的检验：γ = 1 时它与单元模型在 S⁺ → S⁺(1 − S⁻) 下逐对相同（误差 < 10⁻¹²，`tests/test_rs.py`）；γ > 1 时两个方向的 S⁺ 同时求解，期望计数与目标的最大相对误差 < 0.1 %。

## 5. 资源

Gate 4 有记录的 CPU 时间 2.03 核时：试验 301 秒，两次消融 314 与 269 秒，超参数选择 5,087 秒，结构与功能裁判的空跑 913 与 432 秒（`results/g4/*.json` 的 `cpu_s`）；另有两次中止的结构空跑与一次被覆盖的功能空跑，约 0.4 核时。加上 Gate 3 的 1.91 核时，开发累计约 4.5 核时，低于 24 核时上限。没有使用 GPU（`GPU_RESOURCE_DECISION.md` D3）。

空跑（`results/g4/structure_dryrun.json`、`function_dryrun.json`）只检验代码路径：结构空跑的"目标"W8、W5、W6 都在训练数据中，数字没有意义；功能空跑用开发列的内部划分，与 Gate 3 的数字一致（A-real 0.114、A-er 0.105、A-rewire 0.124、A-none 0.357）。判决映射用空跑输出做了冒烟检验（键名全部对上）。T4 裁判用与真实记录同形状的合成数组跑通（真实记录在冻结之后才下载）。
