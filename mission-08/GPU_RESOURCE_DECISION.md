# Mission 08 GPU 资源判定（只追加）

每条判定在 `CPU_CONTINUE` / `REQUEST_GPU_BENCHMARK` / `REQUEST_GPU_EXPERIMENT` / `INCONCLUSIVE_RESOURCE_LIMIT` 中选一个，并写明推翻它所需的新测量（任务书 §10A.2）。数字注明 **[测]**（实测）或 **[估]**（估计）。

本机：Apple M4 MacBook Air，arm64，10 核（4 性能 + 6 能效），16 GB 统一内存 [测，见 Mission 06 记录]；磁盘剩余 4.0 GiB / 228 GiB [测，2026-10-25T01:51Z]。

## D1 — 2026-10-25T01:55Z，Gate 0–1

- **判定：`CPU_CONTINUE`。**
- **依据：** Gate 0 是对 Mission 01–07 文档、代码与结果的审计；Gate 1 是文献阅读、许可证与数据核查。两者没有张量计算，也没有模拟负载。
- **推翻条件：** 无。Gate 0–1 不会产生计算画像；第一次有意义的判定在 Gate 2（工作量估计）和 Gate 3（CPU 参考实现实测）之后。

## D2 — 2026-10-25，Gate 2（预注册之后）

- **判定：`CPU_CONTINUE`。**
- **依据：** 预注册的全部计算（`PRE_REGISTRATION.md` §2–§6、`RESOURCE_BUDGET.md` §3）都是小规模任务：180 个神经元、约 3.2 万个神经元对的逐对递推与网格搜索；约 150 × 150 的矩阵求逆；T4 的 5 个输入时间序列的组合。估计开发 < 10 CPU 核时 [估]，确认 < 5 CPU 核时 [估]。瓶颈是 Python 控制流与网格搜索，不是能放到 GPU 上的大张量运算。
- **三个选项的比较：**

| 选项 | 是否可行 | 理由 |
|---|---|---|
| 本地 CPU | **可行** | 估计远低于 24 / 40 核时的上限 |
| 便宜 GPU（24 / 32 GB） | 不需要 | 没有能从 GPU 得益的负载；数据传输与环境准备的开销会超过计算本身 |
| 96 GB GPU | 不需要 | 同上；显存不是任何一步的约束 |

- **唯一可能需要 GPU 的工作，以及为什么不做：** 用置乱或规则生成的连接组重新训练 flyvis 模型（Lappalainen 缺少的对照；审阅代理估计每个模型数个 GPU 小时 [估]，50 个模型的集合约 100–300 GPU 小时 [估]，另需下载 5.6 GB 的 Sintel）。本轮的果蝇检验不需要任务训练（`PRE_REGISTRATION.md` §4 用实测输入响应），因此不做；为了使用 GPU 而加入这项工作违反任务书 §0 第 8 条。
- **推翻条件：** (1) Gate 3 的实测显示 R1 的单个配置超过 2 CPU 核时，且向量化之后仍超过；或 (2) Gate 4 的候选需要一个参数量 > 10⁶ 的可训练模型。出现任一情况时，先在 CPU 上测小样本吞吐与内存，再按 §10A.2 判定是否值得申请短时 GPU 标定会话。

## D3 — 2026-10-25T04:35Z，Gate 4 结束、Gate 5 冻结之前

- **判定：`CPU_CONTINUE`。** 确认阶段不申请 GPU。
- **实测 [测]：** 单个 R1 配置（10 × 10 网格，180 个神经元）约 150–250 CPU 秒；论文的 40 × 40 网格两个变体合计 4,981 CPU 秒；互惠二元组版本每个网格点约 4 秒、每次拟合约 400–700 CPU 秒；Gate 4 的超参数选择 5,087 CPU 秒（6 个进程，墙钟 17 分钟）；结构裁判在开发目标上的空跑 913 CPU 秒（自助法 50 次），功能裁判 432 CPU 秒。开发累计约 4.5 CPU 核时（有记录的 3.9 小时加上中止的空跑与探索），上限 24。
- **确认阶段的估计 [估]：** 结构裁判（自助法 2,000 次）约 0.5 核时，≥ 3 突触的敏感性分析再约 0.5 核时，功能裁判约 0.15 核时，T4 可忽略；合计约 1–1.5 核时，上限 40。
- **推翻条件是否出现：** (1) 没有单个配置超过 2 CPU 核时；(2) 没有候选需要参数量 > 10⁶ 的可训练模型（K2 是三参数的组合）。两个条件都没有出现。
- **三个选项：** 本地 CPU 可行且足够；24 / 32 GB 与 96 GB GPU 都没有可加速的负载（瓶颈是逐对递推、网格与自助法的 Python 控制流，矩阵最大 180 × 180）。
- **本轮不会出现的 GPU 需求：** 只有 flyvis 的置乱连接组重训练（D2 已说明不做）与逐只动物的潜变量线性动力系统（Creamer；`NEXT_DECISION_MAP.md`，需要数据许可与集群，不属于本轮）。
