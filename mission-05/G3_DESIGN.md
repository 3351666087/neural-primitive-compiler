# G3：冻结与独立持出挑战的设计（只准备，不运行）

写于第六轮之后。本文件、`G3_GENERATOR_BRIEF.md` 与 `G3_FREEZE.json` 一起提交，构成冻结。持出挑战的生成与运行都需要用户另行同意。

## 1. 为什么需要 G3

- 五个开发轮次（修正案 2–6）中的全部结果，都来自设计者写的达成器、模板与目标，评测性质为 DEV。
- 这些轮次表明：
  - A 的库（Z3 证明的损伤、两两保持与进度）可靠；
  - B 能从 N = 5 的观察中学到增量规律与选择规则。
- 但它们都没有面对**设计者没有见过的组合原语**。G3 检验冻结的系统在独立产生的新达成器上是否仍然可靠：
  - A：能否用通用的推导证明新达成器的合同；推出的证书与控制器是否正确；
  - B：只观察新达成器在 N = 5 上的行为，能否学到其规律与支撑集，而不被骗。

## 2. 范围与声明的语言

- **持出的对象**：新的达成器变体，用 ACH-DSL 写成（`experiments/g3/dsl.py` 的文档字符串；生成者拿到的是 `G3_GENERATOR_BRIEF.md` 中的同一定义）。
  - 一个达成器选出目的格 d 与来源格 s，由固定的搬运宏交换其内容。
  - 语言规定了格子类型、区域（含区域的交与"距离 d 不超过 k"）与选取方式（最左、最右、左数第二、右数第二、离 d 最近）。
  - 持出的是"语言中的哪些程序"，语言本身由本会话设计。
- **语言比 B 的规则文法宽**：B 的文法只有单一区域与最左/最右。区域的交、`within`、`second_*`、`nearest_to_dest` 以及非 GROUP 原子上的窗口，都在 B 的文法之外。
- **不在 G3 中**：新的模板族、新的原子类型、新的目标语言。目标沿用 98 个 DEV 目标（PA-1 的 7 个与 PA-2 的 91 个）。

## 3. 冻结的内容

- 库与第二至六轮的学习器（`experiments/lib/`）。

  - `a_dsl.py`：A 的合同表与对真值的可靠性检查；

  - `specs_library.json`：库的 8 个达成器的 DSL 表达。
- 本文件与生成者说明。

## 4. 测量（`run_g3.py`）

1. 校验每个规格；只运行合法的规格，不合法的计数报告。
2. **真值**：对每个达成器实例，在 N = 3..7 的全部状态上穷举，得到各模板的一步增量最大值、两两保持的反例与适用性的反例。
3. **A 的合同表**：
   - 损伤上界与两两保持由 Z3 对一切 N 证明；
   - 进度 = 自身度量的下降由 Z3 证明，且适用性在 N ≤ 7 上没有反例 [M]；
   - 对照真值检查可靠性，并计算校准率：在真正有进度的实例中，A 认证了多少。
4. **构造**：98 个目标，A-P′ 与 A-P，证据规则 TZ，分别用"只有持出达成器"与"库 + 持出达成器"。
   - 每个构造的控制器都由 `cir_dsl` 生成，经 J1-sym（V_train 与 N = 9、12、15）与 J2（N = 6 全部实例）裁判；
   - 至多 10 个使用持出达成器的控制器编译为网络，做 J1-net 锁步检查。
5. **B**：每个实例只在 N = 5 上观察 n = 1000 与 n = 200 个合格状态（含达成器不移动的状态）。
   - 学习 B-GRAM 规律与 B-RULE 版本空间；
   - 在 N ≤ 7 上模拟版本空间；
   - 检查真实的移动是否总在 B 的移动之中（"漏掉"），以及 B 的上界是否低于 N ≤ 7 的真实增量；
   - 用 B 的表做 A-P′（证据 BX），并用 A 的表复核证书。

## 6. 规程

1. 用户同意后，开启一个**独立会话**（全新上下文，独立文件夹，不读取本仓库），把 `G3_GENERATOR_BRIEF.md` 原样交给它。

5. 结果原样报告；冻结之后的任何分析都标注 POST-HOC。

## 7. 有效性威胁

- **语言由本会话设计**。持出的只是语言中的程序；对语言之外的达成器（例如非交换的宏、新的原子）没有任何结论。
- **生成者与设计者属于同一个 LLM 家族**，设计偏好可能相近。说明要求用到语言的每一种构造，以增加多样性。
- **真值只到 N = 7**。A 的损伤与保持是对一切 N 的证明，但"适用性"、B 的规则与支撑集都只有 N ≤ 7 的证据。
- **危险格规则**：真值与 B 的观察都在危险格规则开启的状态上进行；规则关闭的目标只由裁判检查。
- **通用推导的代价**：A-P 对任意 ORDER 达成器只能用度量的最大值（K²/4）作为步数上界。在自检中，这使库的 A-P 从 36 个目标降到 29 个（失去的 7 个都依赖 O1 的手证上界 K/2）。
- **独立性只能由说明约束**：生成者与本会话在同一台机器上，"不读取本仓库"无法强制。

## 7a. 自检（DEV，`experiments/g3/selfcheck.json`）

库的 8 个达成器（12 个实例）用 DSL 重写后，通用流程逐项复现了库：
- 选择：3,524,604 个状态上与 `model.select` 0 处不同；
- 控制器：66 个计划、339,825 次闭环运行中，结果与步数 0 处不同；
- 真值：与 T7 逐项相同；
- A 的表：与 TZ、TZ-P2 逐项相同；
- 构造：A-P′ 重建 TZ 的 30 个目标；A-P 重建 29 个（见第 7 节）；
- B：版本空间与第六轮相同，0 危险。

## 8. DEV 干跑（`experiments/g3/dev_dryrun.json`；设计者写的 8 个新达成器，已看过，不是持出）

8 个规格，15 个实例，其中 3 个规格在 B 的文法之内。运行 849 s 墙钟，其中真值 232 s CPU。

**A**：
- 可靠性检查全部通过：
  - 没有低于真值的损伤上界；
  - 没有带反例的保持证明；
  - 没有被真值否定的进度认证；
  - A 构造的控制器 0 失败；
  - 10 个控制器的网络锁步检查 0 处不一致。
- 校准：真正有进度的 8 个实例中，A 认证 7 个。
- 只用这 8 个新达成器，A-P′ 构造 30 个目标，A-P 构造 27 个。

**B 的第一版暴露了两个问题，冻结前已修正**：
1. **B 没有适用性证据**：第一版 B 只看到"移动了"的观察，于是认证了一个在区域没有空格时会卡住的达成器（DEV-Z-emptyonly）。由 B 的表构造的控制器有 14 个在裁判下失败，A 拒绝了全部这 14 个证书。
   - 修正：B 的观察包括"合格但没有移动"的状态。只有在观察中从未卡住的达成器，B 才认证进度。这是有限样本的证据 [E]。
   - 修正后，B 构造 21 个目标，0 失败。
2. **"危险"的定义**：真值的增长规则（N = 7 的最大值超过 N = 6）在一个 OOW 条目上误报为 ∞，而该条目的增量结构上不超过 1，A 证明了上界 1。
   - 修正：G3 中"危险"指 B（或 A）的上界低于 N ≤ 7 上实际观察到的增量；增长规则的结果另行报告。

**B 在文法之外会出错**：
- 两个文法之外的达成器（DEV-Z-window 的区域交，DEV-G-within 的 within 与 nearest）在 N = 5 上有与观察一致、但在 N = 6、7 上漏掉真实移动的规则：分别漏掉 3,231 与 1,415 个状态。
- 由此每个样本量各有 2 个上界低于观察到的增量。这些实例都因观察到卡住而被 B 拒绝进度，所以没有进入任何证书。
- 文法之内的 3 个规格（4 个实例）：版本空间非空，0 处不一致，0 个低估。

**据此写定的预测**：Q3 把"B 的证书"单独列出；Q4、Q5 区分 B 的文法之内与之外，并预期文法之外会出现漏掉（Q5）。在干跑上 Q1–Q6 全部成立，但这只是一致性检查，因为阈值参照了干跑。

## 9. 锁定的预测（与 `experiments/g3/score_g3.py` 一致）

| 编号 | 预测 | 不成立时的含义 |
|---|---|---|
| Q1 | **A 的可靠性**：(a) 由 A 的表构造的控制器（A-P、A-P′；只有持出达成器 / 库 + 持出达成器）在 J1-sym 与 J2 上 0 失败；(b) 没有 PROVED 的损伤上界低于 N ≤ 7 上观察到的增量；(c) 没有 PROVED 的保持条目在 N ≤ 7 上有反例；(d) 没有进度认证被 N ≤ 7 的真值否定；(e) J1-net 锁步 0 处不一致、0 失败 | A 的通用推导或规格 → CIR → 网络的链条在独立输入上有错；找出出错的组件，A 的可靠性结论退回 DEV |
| Q2 | **A 的校准**：在 N ≤ 7 上真正有进度的实例中，A 认证 ≥ 75 %（这类实例少于 5 个时为 INCONCLUSIVE） | 通用的必要约束对独立设计过于保守，需要更多约束族 |
| Q3 | **B 的证书**：由 B 的表（n = 1000 与 200）构造的控制器 0 失败 | B 的拒绝机制（卡住的观察、版本空间）不足以挡住独立设计中的错误 |
| Q4 | **B 在文法之内**：文法之内的持出规格的每个实例，版本空间非空（≤ 64 对）、与真实选择 0 处不一致、没有低于观察增量的上界（两个样本量都如此；没有这类规格时为 INCONCLUSIVE） | B 的"规则可从 N = 5 学到"（Z-a）不能推广到独立设计 |
| Q5 | **B 在文法之外**：n = 1000 时，至少有一个文法之外的实例，其版本空间非空却在 N = 6、7 的某个合格状态上漏掉真实移动（没有这类规格时为 INCONCLUSIVE） | 不成立反而说明 B 比干跑中更可靠：N = 5 的观察足以排除所有错误的规则 |
| Q6 | **成本**：整个运行 ≤ 2 小时墙钟，真值 ≤ 30 分钟 CPU | — |

**裁决**：
- Q1 成立：A 的通用合同推导，以及"规格 → IR → 网络 → 验证"的链条，在独立产生的达成器上可靠。这是 G3 的核心结论。范围限于声明的语言，适用性只有 N ≤ 7 的证据。
- Q1 与 Q3 都成立、Q4 也成立：B 的规则学习在文法之内推广到独立设计，而它的错误（Q5）被拒绝机制挡在证书之外。
- 任何不成立都原样报告。冻结之后的分析一律标注 POST-HOC。
