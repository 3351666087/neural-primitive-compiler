# Mission 06 — The Constructibility Frontier

**副题：从未知目标到可迁移认知结构——在独立、真实任务型环境中检验智能能否被直接构造**

> **任务的目的不是交付一个漂亮的 agent，也不是刷新 benchmark 排名，而是尽可能严苛地检验这条命题：一小组可复用的认知/计算原语与组合规律，是否足以使新的复合认知能力按照目标直接构造，而不需要对每一种能力重新大规模训练？若此命题不成立，具体在哪里不成立？**

## 0. 北极星：这究竟是什么研究

终极问题（A）：**是否存在一组足够基础、可验证、可组合的原语与规律，能依据新目标构造具有感知、记忆、绑定、条件决策、规划、纠错和生成能力的执行结构？**

方法问题（B）：**这些原语、表示形式及其构造规律能否从有限的环境观察与主动实验中被发现，而不是全由设计者写入？**

桥接（A↔B）：**B 产生的结构知识必须真实进入 A 的构造；A 在外部新任务中的失败必须推动 B 对假说的修订。** 不接受「独立写一篇发现报告」加「另写一个 agent」的松散并列。

这里的「直接构造」是：在冻结的、可计成本的基础知识之上，输入**目标级规格**，输出一个实际可执行的复合策略/机制/网络，并对成功、失败、不确定以及适用范围给出可检验的理由。不能把完整步骤塞进规格，不能把每个任务答案预写在库里，不能把难题转移为每个测试任务上的无约束 LLM 推理。

不要求证明新计算模型有超过图灵计算的表达力。科学上可能有价值的差异在于：**构造的搜索复杂度、样本效率、组合泛化、保证强度、复用成本、适应能力与结构成本**。若与同知识的经典方法在这些方面都无差异，就接受零假说。

### 延续而不能篡改的 Mission 05 事实

- LINE 的目标级闭环控制链已实现：目标 → CIR → 整数 IF 神经网络 → 环境反馈；网络与 CIR 在**有限抽样**锁步，编译器无通用完整正确性证明。
- 在给定强先验的 LINE/ACH-DSL 中，A 的组合合同能构造经检验的控制器，但同期同库符号搜索更便宜且覆盖更多。开发任务覆盖 49/98；不是「组合规律已胜过传统规划」。
- B 从小规模状态观察恢复了**设计者给定文法内**的交换、局部势函数和选择规律；文法本身未被自主发现。
- G3/G4 持出的是**新达成器规格**，不是新目标族或新领域；新规格仍在原 ACH-DSL 内、仍按同一目标池测量，生成者仍属于同一 LLM 家族。G4 的 41/42 是 N≤7 意义下「真正有进度的达成器实例」中获得证书的数量，**不是完成 41/42 个复杂目标，更不是全规模保证**。
- **必须优先修复的证据环**：`mission-05/experiments/r8/zpp.py` 的进度认证使用 `tr[k]["applicability_cex"]`，即 N≤7 的真值穷举结果。下降部分与适用性部分证据强度不同。不能再把「参数化的下降定理」等同于「完整策略任意规模正确」。
- Mission 04 外部表示发明确认失败，暴露了「0 是背景」等隐性设计者先验。负结果必须保留。

## 1. Mission 06 的四个杀手级科学问题

### F1：独立构造性（Independent Constructibility）
在**第三方原样维护的任务型环境**中，冻结一套构造体系后，系统能否只看新的目标与合法观察，就组合出新的闭环执行策略？新目标族不能仅是换常量、换颜色或换达成器名字。

### F2：适用性与保证不借裁判（Non-circular Certification）
构造器能否独立从公开的环境模型、可观察证据与可证明前提，得到每个技能的**可执行性/适用性**、进度和安全证明义务？独立裁判持有的隐藏真值/完整状态/解答与穷举表不得作为构造器输入。

### F3：未知下的结构发明（Representation and Skill Invention）
遭遇现有技能库无法完成的任务时，系统能否提出至少一种**此前不在冻结技能文法内**且具有可复用契约的中间表示/技能/组合规则，并用主动区分实验验证它，随后迁移到新任务？「把预置语法的参数拟合出来」只能算参数发现，不算形式发明。

### F4：跨领域规律而非跨领域 API（Cross-domain Constructive Law）
至少在**两种语义显著不同的第三方环境**中，尝试重用一个共同的组合规律/合同类型（例如进度、保持、适用性、恢复或观察抽象）；允许各域感知与执行适配器不同，但必须明确重用的到底是什么。若不能迁移，给出最小反例并说明哪一个逻辑假设破裂。

**四问无需全得到肯定答案；但必须获得强而诚实的实验答案，不能以「运行了很多测试」替代。**

## 3. 把「不给 oracle」写成可检查的工程限制

最容易重犯 Mission 05 的漏洞：验证器生成真值，再喂给构造器当证明前提。必须实现下列边界。

**Constructor 容许的输入：**
1. 新目标的自然语言或目标级逻辑规格；允许冻结的、统一的语义解析器，但禁止逐题人工翻译成答案。
2. 任务开始后代理本应能看到的截图、DOM 可访问性树、工具返回、文本观察等；若换成结构化状态，必须作为另一个明显标注的特权消融条件。
3. 冻结的技能库、先验、已学习规律与对应可核验证书。
4. 明确计费的、允许的主动环境交互或离线探索数据。

**Constructor 禁止的输入：**
- 评分脚本的真实结果、评测答案、隐藏环境真值、未来动作序列；
- 由独立裁判对目标任务穷举得到的 `applicability_cex is None` 之类真值标签；
- 以持出结果修改目标解析、技能模板、颜色/对象角色、解释规则或阈值；
- 逐题写代码、逐题预设行动计划，然后假称「根据原语直接构造」；
- 用每个任务无限次免费调用 LLM 进行自由推理，再把输出包装成编译结果。

**必要的证据类型：**
- `P`: 具有明示前提的参数化定理，说明独立证明器与可信基。
- `M`: 穷举或模型检查仅对**指定界限**有效。
- `E`: 抽样试验、统计置信区间或有限轨迹检查。
- `U`: 无法确定/资源超限。

适用性不能被 `M` 偷换为 `P`。若确实需要假设「动作最终能够执行」，必须要么给出独立环境契约/公理（标注信任），要么以运行时监控和恢复机制将其转化为明确的条件保证。随机动态下可研究概率式保证，不得宣称无条件必达成。

## 4. 所需的智能成分：不是完成若干点击，而是构造复合能力

为了排除简单脚本，正式目标池里必须有下列交互的**组合实例**，且各自至少有一个自外部来源的、未见过的任务族：

- 关系与变量绑定：目标依赖多个同类型对象及其关系，不能仅依位置/固定 ID。
- 长程记忆/部分可观测：执行依赖先前见过而当前不可见的信息，测试历史交换、返回路径和信息失效。
- 分支与闭环纠错：行动结果不确定或部分失败，需要根据反馈改变策略。
- 多约束/安全：达到目标同时不破坏指定资源、记录或不可逆状态；必须有反事实检查。
- 新组合深度：冻结时常见的是少量技能组合，持出时需要更长依赖链或此前未同时出现的技能对子。
- 未知属性：一种重要前提或环境规律未在技能库中明示，需要主动实验、表示修改或诚实弃权。

**不允许用单个原子技能成功率代替这些复合目标的结果。**

## 5. 竞争假说与零假说（代码之前锁定）

| 假说 | 可鉴别的预测 | 致命反例 |
|---|---|---|
| H-COMP 组合合同能提升长期可靠性 | 同样技能库/信息/预算下，在更深或更复杂的组合中安全失败率、复用验证成本、稳定性有可测优势 | 同库行为树/HTN/PDDL 的成功、安全、成本各项不劣，且具有同等证书 |
| H-DISC 规律从环境中发现并进入构造 | 冻结后的未知任务中，B 的新规律产生新增可执行策略或减少真实任务的适应代价 | 新规律仅是预写语法参数，或从未影响任何构造决策 |
| H-REPR 表示形式发明有独立收益 | 在已有机制类不可表达的真实失败上，新增的可复用抽象让未见任务成功，且与更大的手写 DSL 比较合理 | 收益来自答案模板、人为加入评测知识或增大候选空间而非学到的结构 |
| H-XFER 至少部分构造规律跨域成立 | 在两个独立环境中某些合同/组合推理不改动，只替换域适配器；可预先预测失效条件 | 迁移前必须完全重写原语与合同，因此只是软件接口复用 |
| H0-CLASSIC 强零假说 | 同信息/预算的经典规划、程序综合与层次策略没有更差；所谓原语只是已有方法编码 | 方法出现可重复、信息匹配且统计可靠的结构或保证优势 |
| H0-SPEC 原语与技能知识泄漏 | 只要剥离目标探测器、预置达成器、隐藏真值，就失去所谓直接构造性 | 剥离后，系统仍能在独立任务上构造并适应 |

**实验必须能让自己的主张输。** 先验泄漏消融、完全状态消融、技能库成本消融、目标族外推、无 B、无组合合同等均要事先登记。

## 6. 必须拥有的公平基线与成本账本

同一任务、同一合法观察、同一安全约束、尽可能相同的技能/动作库：

**B1 — Same-knowledge classical：** 同库 HTN/behavior tree / PDDL-like planner 或程序综合器，允许任务级搜索，记入搜索 CPU 和知识库成本。不能拿弱的平面 FSM 当唯一对照。

**B2 — Strong agent：** 在相同环境里由 LLM 作任务级规划与执行的强基线（若允许联网或付费，调用次数和成本明示）；这条对照回答「何必构造，直接让大模型想不行吗」。不得借它的任务答案为构造器生成技能。

**B3 — Ablations：** 去掉证书、去掉被发现的规律、去掉记忆、去掉恢复、去掉抽象、去掉神经后端；这些是归因而不是强基线。

**B4 — Best available reference：** 若官方 benchmark 提供可用的强公开 baseline，给出语义差异、硬件条件与不可比部分。不要为了漂亮数字挑弱版本。

成本：
\[
C_{total}(k)=C_{library\ discovery}+C_{library\ verification}+C_{environment\ exploration}+k\cdot (C_{new\ goal}+C_{runtime})
\]

每一项区分 CPU/GPU 墙钟、测试环境交互、模型 token/推理成本、人工/LLM 设计成本、证明成本、代码量/库复杂度。未知开销必须写 UNKNOWN，不得当作零。绘制随着目标数量和难度变化的摊销曲线；明确何时与同库搜索相交，何时永远没有收益。

注意：**验证优势也可以是科学结果，但不要改口把「速度优势」包装成「证明优势」。**

## 7. 实验次序与强制闸门

### Gate 0 — 独立复核 Mission 05 的可信基（优先，不能跳过）

1. 画出 `r8/zpp.py → truth.tables → A-P/A-P′ → CIR → network → J1/J2` 的逐字段信息流。
2. 隔离 `applicability_cex` 及全部裁判内真值，不允许 A/B 的新算法导入评分侧 `truth`。
3. 尝试对适用性给出参数化证明，或生成有明确假设及运行时监控的证书。若失败，给出反例与失效规模，保留有界模型检查作为 `M`。
4. 针对 `compile_cir` 建立明确受限的语义保持定理/归纳不变量；若无法证明，输出最小反例/UNKNOWN，绝不以抽样锁步充当无界证明。
5. 验证没有把控制器成功事后替换成原子进度认证的统计。

**G0退出条件：** 可追溯的可信基图、每条声称的证据等级、一个尝试真正剥离 oracle 的构造实验、至少一份严格的反例搜寻报告。不能只写审计报告。

### Gate 1 — 外部世界可用性与预注册（不允许悄悄缩水）

1. 查验 WorkArena++/WebArena 等真实工作流基准的安装、许可、认证账号、合法运行方式、资源与苹果芯片兼容性；另查验 ALFWorld 或等难异质环境。
2. **先选环境和评测任务族，再看开发结果**；锁定选择理由和为什么不能算人为设计的玩具。
3. 由独立者保管持出源/任务索引；冻结前只接收 API 文档和开发许可观测。
4. 生成 `MISSION06_FREEZE_PLAN.md`，含环境 commit、容器或安装记录、任务家族划分、污染审计、评测封存规则、强基线、预算和失败时处理。

**G1退出条件：** 一个真实任务型主域和一个异质挑战域可用，或如实 `BLOCKED` 并请求用户决定。禁止直接退化为自己写的二维地图。

### Gate 2 — 反证优先：已有系统原样外推

冻结 Mission 05 的认知合同核心/构造 API；只能构建透明的 observation 与 action 适配器（这些适配器的知识成本须记账）。先让现有体系在外部开发目标里失败；分别记录失败是：
- 无法表达目标；
- 无法感知/绑定对象；
- 没有需要的技能；
- 缺少可证明适用性；
- 无法处理长期依赖或失效恢复；
- 搜索或编译成本爆炸；
- 理论假设与环境动态不匹配。

**硬要求：** 至少抽取 3 个对后续研究路线有不同影响的最小失败机制；对每种先提出 ≥2 个竞争解释，再设计区分实验。先不要写大框架。

### Gate 3 — 深挖一个真正缺失的构造规律

只选择 Gate 2 中**科学信息量最大**的一种失败，不按最容易刷分的类别选。要求探索：
- 传统 HTN/行为树/广义规划给出的最强解释；
- 原语组合合同的升级，例如 belief-aware applicability、资源效应、条件保持、失败恢复的可组合证明；
- B 对规律或结构的归纳：主动实验应能区分假说，而不是被动收集任意数据；
- 新规律是否真正改变了未见目标的构造决策。

允许一次明确的范式修改；但必须和原方案公平对比、提交负结果、冻结新增先验。若发现跨域不存在共享规律，应尝试构造**最小跨域反例**并研究它揭示的表达边界。

### Gate 4 — 外部盲确认，必须能证伪

在任何结果产生前，独立冻结：执行代码 SHA、技能库、所有 LLM 提示与模型版本、预算、目标家族、统计指标、容许的环境访问权限、预报范围、每种预测失败时的裁决。

正式测量至少包含：
1. **全目标成功率**：任务是否实际完成，置信区间；不是达成器认证率。
2. **安全性/恢复率**：副作用、安全约束违反、失败后恢复与弃权校准。
3. **新组合泛化**：训练中未同时出现的技能组合、较长依赖链以及新目标族。
4. **未见环境变化**：观察缺失、外部布局/记录变动、非确定执行；这些变化必须合法且非任务专用捣乱。
5. **端到端证据**：只在明确前提下声称证明，否则测有界验证或统计正确性。
6. **同库基线/成本**：经典 planner 与 LLM agent 不能缺席；无法部署则其对应优势声明为 `INCONCLUSIVE`。
7. **跨域法则**：仅适配器变化而合同/组合推理冻结不动；失败记为失败。

不得仅以超过一个低水平绝对成功率来宣布构造理论成立。预报里必须有相对于强基线的**有意义效果量及不确定性**，并报告覆盖与弃权的取舍。

### Gate 5 — Verdict：什么是真的，什么还不知道

每条结论写清楚：
- 哪个新知识是由证据产生、哪个由开发者/预训练提供；
- 在哪里真正构造了新目标行为结构；
- 哪些语义保持/合同是 P、M、E、U；
- 哪些任务必须逐任务推理、搜索或再训练；
- 相同先验的经典方法是否同样做到；
- 有没有证明新表示或新原语而不只是旧方法的别名；
- 发现能力随组合深度、环境复杂度、库规模的增长曲线；
- 什么最小反例否定了最强假说；
- 下一轮真正值得测试的是什么。

Mission 可停在任何 Gate。不要为了写 `COMPLETE` 而越过证据不足的关口。

## 8. 特别禁止的「高级作弊」

1. 用 LLM 在每个持出任务上自由阅读观察、生成完整步骤，随后把步骤编译成神经网络，并声称系统自动发现了规律。
2. 把真正的目标成功检查、动作适用性或隐藏世界状态作为构造器可调用的 oracle。
3. 强基线没有相同感知/原语/预算，却声称组合理论更高效。
4. 官方 benchmark 太难，就另写一个与自己原语一一对应的新任务世界，然后宣布跨域成功。
5. 在评测后逐题补 primitive、goal parser 规则、异常处理、动作模板，再统计提升；评测后修改只能作为 DEV/POST-HOC。
6. 「可证明」只证明组件，漏掉 perception、applicability、scheduler、environment、compiler 的缺口。
7. 从预置的新 DSL 搜到一个程序，却把它叫作发现了前所未有的表示形式。
8. 把时间花在重新布局 README、机械增加文件数、扩大 CI 测试规模，却回避可能推翻主假说的实验。
9. 把证据锁定改成形式主义：先看答案再填 manifest / 假说书。
10. 为了用户想要宏大的愿景而夸大科学结论。

## 9. 极限反证题（选一个尝试；成功不是必须条件）

在外部正式持出任务中，找到一个**现有库中不存在完整计划/脚本**、还需要记忆 + 关系绑定 + 长程依赖 + 一次反馈驱动的纠错、且含可检验安全约束的目标。冻结后让系统：

1. 从目标和合法观测中决定所需能力；
2. 若原语不足，基于开发阶段证据提出可验证的技能或抽象，而非读持出答案；
3. 通过重用已有合同而不是重新验证所有状态，从技能组合构造闭环执行器；
4. 产生可独立检查的适用性/安全/进度条件，不能从裁判查询它们的真值；
5. 在一个新的任务族或第二个环境中用同一个构造规律再次成功，或严格说明其不可能原因；
6. 对同知识的最强符号构造器报告成功率、成本与失败差异。

**如果这件事做不到，记录到底断在 1–6 哪一步。发现边界，比拿一组定制题交出 100% 分数更有价值。**

## 10. 交付物与真实的结束方式

建议研究文件（名称可调整，含义必须保留）：

- `mission-06/NORTH_STAR.md`：精确假说、非目标、如何失败。
- `mission-06/M05_TRUST_BOUNDARY.md`：从 Mission 05 开始的独立审计、oracle 剥离及可信基。
- `mission-06/ENVIRONMENT_SELECTION.md`：官方环境、部署、成本与选择锁定。
- `mission-06/KNOWLEDGE_PROVENANCE.md`：每个技能/目标检测器/特征/文法/提示词的知识来源。
- `mission-06/HYPOTHESES.md`：竞争理论、强零假说、最小反例。
- `mission-06/EXPERIMENT_PRE_REGISTRATION.md`：锁定的预测、阈值、任务分割、held-out 权限、预算。
- `mission-06/EXPLORATION_LOG.md`：至少每轮「观察→理论→区分实验→反例→修订」，含被证伪的预测。
- `mission-06/RESULTS.md`：可复现原始数据、置信区间、各个基线与分层。
- `mission-06/CONSTRUCTIBILITY_VERDICT.md`：科学判决、P/M/E/U 证据地图、不可构造例、未来关键未知。
- 必要的 `src/`、`experiments/` 与测试。不要为每个名词都创造一个空壳模块。

进度保存：**每次冻结预测、代码先于结果、重大反例、范式修订时分别 commit；不要把所有阶段攒到最后，也不需要每个可运行脚本都宣布「完成」。**

计算开销：先做 30–60 分钟以内的部署可用性与低成本 pilot；任何超过预登记 CPU/模型/在线环境预算的实验应 `RESOURCE_LIMIT` 并保存部分结果，不允许无限烧钱或从用户真实账号拿隐性预算。若环境权限与资源是 blocker，应立即报告，不能伪造环境成功。

## 11. 立即开始时该做什么（**只给 Opus 的首轮执行命令**）

1. 阅读并核对 Mission 05 中适用性真值反馈路径，编写严格的证据/信息流审计并尝试剥离；必要时构造一个最小循环论证反例。
2. 做官方外部环境的**可行性报告**与知识泄漏审计：主域优先 WorkArena++/WebArena，异质域优先 ALFWorld；只用官方文档与安装测试，不查看评分答案。报告 M4 Mac 资源、是否需要凭据/账号/虚拟机、如何合法部署。
3. 给出 H-COMP、H-DISC、H-REPR、H-XFER 与 H0 的**可区分预测**，选一个有可能在低成本下明显失败的先导实验。
4. **在获得用户对真实环境的批准与必要资源之前，不要替换成玩具，不要声称进行了外部确认。**
5. 只有 Gate 0/1 通过后才进入大规模实验。科学判断允许 `NOT_SUPPORTED`、`INCONCLUSIVE` 和 `BLOCKED`。禁止为了赶进度宣称 Mission 06 COMPLETE。

**最终提醒：你的使命不是让所有目标都通过测试，而是严苛检验能否存在一条从认知目标、经规律发现与原语组合、通向真实可执行结构的可扩展构造路线。**
