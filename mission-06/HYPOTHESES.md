## 0. 来自 Gate 0 的约束（Mission 05 的教训）

- 一个控制器的"可证明"必须覆盖感知、适用性、调度、环境与编译器的全部缺口（任务书 §8.6）。
- Mission 05 中，适用性只有有界证据；它在 LINE 中是对构造器宏模型的穷举，而不是对环境的证明。
- G0 的结果：在 ACH-DSL 内，适用性可以不读真值、对一切 N 证明（APP-R，122/122）。但证明依赖一个可数、完全可观察的状态抽象，以及一份手写的松弛编码。G0 还显示，"全部合格状态"上的适用性相对于具体目标是保守的。
- 外部环境里没有可穷举的宏模型。所以适用性只能是以下三者之一：
  - (i) 由公开的环境契约推出（契约本身记为信任）；
  - (ii) 由运行时监控变成条件保证（"若前提被观察到不成立，则弃权或恢复"）；
  - (iii) 统计估计 [E]。

## 1. 假说与可鉴别预测

| 假说 | 在本设置中的可鉴别预测 | 致命反例 | 首次可检验于 |
|---|---|---|---|
| **H-COMP**：组合合同提升长期可靠性 | 技能库、观察、预算都相同，比较带合同的组合（前置、效果、保持、适用性监控）与不带合同的同库组合（B3 消融）。在组合深度 ≥ 3 的 WorkArena++ L2 工作流上，前者的**副作用 / 安全违反率**更低、**弃权校准**更好，且全目标成功率不低于后者。与同库行为树或 HTN（B1）相比，至少有一项可测优势：失败前弃权率、验证复用成本，或深组合上的稳定性 | B1 在成功、安全、成本上都不差，并能给出同等强度的证书 | Gate 2（原样外推）的失败谱；Gate 4 |
| **H-DISC**：规律从环境中发现并进入构造 | B 在开发族上用主动实验得到的规律（例如某类表单字段的前置或副作用规律），在冻结后的持出族上**至少改变 1 个构造决策**，并比"无 B"多成功 ≥ 1 个持出任务；或者在同样成功率下少用 ≥ 30 % 的环境交互 | 规律只是预写文法的参数；或从未改变任何持出构造 | Gate 3 |
| **H-REPR**：表示发明有独立收益 | 在冻结文法无法表达的真实失败上（Gate 2 记录），新增的可复用抽象让 ≥ 1 个未见族的任务成功。在同等描述长度预算下，这一收益大于"更大的手写 DSL" | 收益来自答案模板、评测知识，或单纯扩大候选空间 | Gate 3 |
| **H-XFER**：至少部分构造规律跨域成立 | 同一套合同类型（进度、保持、带监控的适用性）与组合推理，在 WorkArena 与 ALFWorld 中都不改动，只换适配器。事先写出失效条件：例如 ALFWorld 中，适用性依赖未观察的容器内容，必须换成"信念 / 监控"形式 | 迁移前必须重写原语与合同，因此只是软件接口复用 | Gate 3/4；先导实验 P-ALF-1 |
| **H0-CLASSIC**：同信息的经典方法不差 | 同知识的 HTN、行为树或 PDDL 规划器（B1），在成功率、安全与成本上不劣于构造器 | 构造器有可重复、信息匹配、统计可靠的优势 | Gate 4 |
| **H0-SPEC**：原语知识泄漏 | 剥离设计者写的技能、检测器与 oracle 之后，可构造的持出任务数接近 0 | 剥离后仍能在独立任务上构造并适应 | Gate 2 起持续记账 |

**本会话的事先估计**（记录在案，供日后对照）：
- 由 Mission 05 的 PA-1（同库搜索更便宜且覆盖更多），H0-CLASSIC 很可能成立。
- 由 Mission 04 的经验，H0-SPEC 在外部环境中大概率至少部分成立。
- H-COMP 最可能成立的形式，不是"更会构造"，而是"更会知道自己何时不能构造"（弃权与安全）。

## 2. 低成本、可能明显失败的先导实验

### P-ALF-1　适用性的可观察性（ALFWorld 文本版；需要用户批准 D3）

- **问题。** Mission 05 的合同类型把适用性当作当前状态的谓词，并在构造时认证。在部分可观察的家务环境中，这个合同类型还能不改动地使用吗？
- **设计（≤ 60 分钟 CPU）：**
  - 固定一组与任务无关的技能模式，加上它们公开的前置条件：前往容器 r、打开 r、从 r 取物体 o、把 o 放入 r、用微波炉加热 o、用冰箱冷却 o、在水槽清洗 o。前置条件来自 ALFWorld 文档中的动作语义，是设计者知识，记入 `KNOWLEDGE_PROVENANCE.md`。
  - 在 valid_seen 的游戏上，用与目标无关的探索策略各跑 20 步（随机合法动作，种子固定）。
  - 在每一步，对每个与目标相关的技能实例，只用到当前为止的文本观察历史判定"适用 / 不适用 / 未知"。判定者是构造器侧，不读 PDDL，也不读 `admissible_commands`。
  - 裁判侧用 `initial_state.pddl` 与环境状态给出真实适用性，只用于评分。
- **度量：**
  - U = 判为"未知"的比例；
  - W = 判为"适用 / 不适用"但与真实不符的比例。
- **预测：**
  - H-XFER 的朴素形式（合同类型不改动）预测 U ≤ 0.1 且 W = 0。
  - 本会话的估计是 U ≥ 0.5：容器在打开或访问之前内容未知。
  - W > 0 意味着观察到的文本与状态之间存在适配器无法消除的歧义。
- **判定：**
  - 若 U ≥ 0.5，Mission 05 的适用性合同类型不能原样迁移。这是一个明确的最小失败机制，进入 Gate 2 的失败分类"缺少可证明适用性 / 理论假设与环境动态不匹配"。
  - 若 U ≤ 0.1，朴素迁移在这一点上成立，Gate 3 的方向需要另选。
- **为什么是好的先导：** 成本低，不需要 LLM，不接触持出数据，结果对 Gate 3 的方向（"带信念的适用性"）有直接影响，而且可能推翻本会话的估计。

### P-WA-0　冻结体系原样外推的第一步（WorkArena L1；需要用户批准 D1、D2）

- **问题。** 冻结 Mission 05 的构造 API，只写透明的观察与动作适配器。在开发种子 ≥ 10 的 L1 原子任务上，构造失败在哪一步？
- **失败分类：** 无法表达目标 / 无法感知或绑定对象 / 缺少技能 / 缺少适用性 / 长程依赖 / 成本爆炸 / 假设不匹配。
- **预测：** 33 个原子任务中，≥ 80 % 首先失败在"无法表达目标"或"无法感知、绑定对象"。理由：LINE 的观察是格子颜色，没有到 AXTree 的通用映射。
- **适配器知识记账：** 每个适配器的行数、写入的规则数，以及用到的任务知识来源。
