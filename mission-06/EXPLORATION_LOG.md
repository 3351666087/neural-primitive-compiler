# Mission 06 探索日志

每轮按"观察 → 理论 → 区分实验 → 反例 → 修订"记录，含被证伪的预测。

## G0 开发期（2026-10-21，锁定 `c0f23d8` 之后、代码提交 `100e8fe` 之前）

### 观察 1：真值的来源

- **观察。** `truth.py` 只导入构造器侧模块（`model.py`、`dsl.py`、`libval*`）。
- **理论。** 任务书把 `applicability_cex` 描述为"裁判穷举得到的真值标签"。按原始代码，它是构造器自己的宏模型在 N ≤ 7 上的穷举。问题是证据等级（[M] 被标成 "TZ"），而不是裁判状态泄漏。
- **后果。** Mission 05 的"0 危险条目"衡量的是 Z3 编码与宏模型的一致性，不是与环境的一致性。由此加入 G0-M1：检验宏模型与"环境 + 编译出的选择"是否一致。

### 观察 2：APP-R 的第一版太弱

- **区分实验。** 在新随机规格（种子 606）上，与 N ≤ 5 的真值比较：0 个错误证明，但 6 个"真值适用、APP-R 未证明"的模型。
- **反例（虚假模型）。** 都涉及 ZONE 原子上的窗口区域。松弛允许窗口放在任意位置，或允许窗口"不存在"，而真实的最右（最左）区段在别处。
- **修订（修正案 G0-1）**，依次加入四组约束：
  1. 窗口外侧相邻格是阻挡格；
  2. 侧区间每 c 格一个阻挡格；
  3. 窗口不存在时，每个区间的阻挡数下界，以及见证格所在区段长度 < c；
  4. 侧区间内每个区间的阻挡数下界。

  每一步都是必要条件，可靠性不变。最终版在种子 607 的 20 个适用实例中证明 12 个。

### 观察 3：N ≤ 5 的适用性不外推，N ≤ 7 余量很小（开发观察）

- APP-R 的无界模型具体化出 8 个真实反例（N = 13..634）。它们在 N ≤ 5 时适用，但在 N ≤ 7 的真值中都有反例，首次出现在 N = 6 或 7。
- 含"距 d 不超过 3"的规格，第一个反例恰好出现在 N = 7。
- **理论（待 G0-A3 检验）：** N ≤ 7 对 k ≤ 3 的固定宽度区域刚好够用。更大的 k 或更宽的固定区域会让 N ≤ 7 的穷举失效。

### 观察 4：编译器在一类合法 CIR 上响亮失败

- **观察。** 冒烟测试中，寄存器从自身或更靠后的寄存器装载时，`compile_cir` 抛出"duplicate signal"。
- **原因。** `cog.prims.cmr` 把尚未建立的 Y 神经元名当作输入通道。
- **修订。** 把定理的范围限定为类 C_K；G0-K2 另外检查 C \ C_K 的程序全部被响亮拒绝。

### 协议偏差（如实记录）

- 第一次冒烟测试是在 12 个 LIB 实例上运行的，所以 G0-A5 不再是盲测（修正案 G0-1 第 2 条）。
- 环境选型的文档调研与 G0 的运行并行进行（只读官方文档与元数据）。
- 正式运行的第一次 `run_app.py` 在算完 N ≤ 7 真值之后、产生任何 APP-R 结果之前崩溃。原因是复现检查假定 G3 存档有 `truth_progress` 字段，实际上 G3 存档只记录了每个实例的适用性（`A.progress[k].applicability_N7`）。修复为按适用性比较，并把真值的保存移到检查之前（提交 `5f9f538`），然后从 `run_app.py` 起重跑链条。`trust_flow` 与 `compile_fuzz` 的结果不受影响。

## G0 正式运行（提交 `100e8fe`、`5f9f538`；结果见 `M05_TRUST_BOUNDARY.md`）

- **观察。** APP-R 证明了 AUD 中全部 122 个真值适用的实例（三个范围），没有错误证明。剥离真值后构造完全不变（G0-C1）。去掉适用性证据则产生 53 个失败的控制器（G0-C2）。
- **理论修订。** Mission 05 循环依赖的实质，是证据等级而不是信息泄漏。在 ACH-DSL 内，这一缺口可以由参数化证明补上，代价是另一份手写编码进入可信基。可信基没有变小，只是换了形式：从"N ≤ 7 的宏模型穷举"变成"手写的松弛编码 + Z3"。
- **被证伪的预测：G0-M1。** 锁定的比较要求完整序列相等。在"适用但不下降"的达成器上，双方都无限循环，序列在不同长度处被截断。POST-HOC 诊断显示真正的不一致为 0。这是测量工具的缺陷，不是模型的缺陷。按协议，判定保持"不成立"。
- **被证伪的预测：G0-B。** 运行脚本崩溃，重算真值使总 CPU 超出预算。
- **附带观察。** 适用性合同按单原子的全部合格状态表述，相对于具体目标的闭环可达状态是保守的：G4-HO 上，无证据构造多出 13 个在裁判下成功的目标。合同可以改成"相对于目标的可达状态"的形式，这正是外部环境中"带信念、带监控的适用性"需要面对的问题。

## G1 ALFWorld 试点与 P-ALF-1（2026-10-21）

- **观察。** 原始命令的适用性几乎总能由文本观察判定（U_P = 0.0014）。"取得目标物体"的前置条件在约 60 % 的步上不可判定（U_M = 0.62；只算解析成功的局为 0.58）。
- **意外的反例。** 判定器的全部 482 个确定性错误都来自同址容器。这是一条从不出现在观察中、但可以由交互推出的环境结构。设计者的信念规则（一个容器一个位置）是隐性先验，与 Mission 04 的"0 是背景"属于同一类错误。
- **设计修订（锁定之前）。** P-ALF-1 的第一稿只测原始命令层，会因平凡的原因失败，改为两层。
- **理论含义。** Mission 05 的适用性合同在 LINE 中可以对一切 N 证明，因为状态完全可观察、可计数。在 ALFWorld 中：
  - 原始动作层可判定，但依赖一条需要发现的结构；
  - 达成器层不可判定，需要"信念 + 存在公理 + 信念上的进度度量"。

  这把 Gate 3 的候选方向收窄为两个可检验的问题：(1) 带信念的适用性合同；(2) B 是否能发现同址关系。

## B2 经由子 agent 的可行性（G1-B2P0）

- 子 agent 作为 B2，在 2 局 ALFWorld 开发游戏上都成功（11 步、4 步），每步约 4,100 tokens。设计者没有接触其轨迹。
- 一局只用最少步数完成，提示了 B2 的知识优势：预训练中关于物品位置的先验。构造器在达成器层"不知道 X 在哪"（P-ALF-1：U_M ≈ 0.6），B2 可能靠先验直接猜中。这是 H0-SPEC 与 H-COMP 比较中必须分离的知识差异：给构造器同样的先验（作为记账的设计者知识），或把它当作 B2 的优势报告。

## G2 原样外推（2026-10-21；结果见预注册 §G2-0、§G2-ALF）

- **观察。** AppWorld 的开发任务分为信息目标（27.5 %）与带运行中关系绑定的状态目标（72.5 %），两者都需要迭代（95 %）。冻结核心的目标语言（状态谓词的合取，变量只在开局时绑定）一类也表达不了。
- **反例。** 在 ALFWorld 上，带监控的公理合同（G2A-1）成功 40/60，所有失败都被检测到；不带监控的 HTN（B1）成功 52/60。G2A-e 被证伪。原因是监控执行了一条错误的设计者公理："一个容器一个位置"。可靠性取决于公理是否正确。
- **理论修订。** H-COMP 的"可靠性"主张需要一个前提：合同中的公理是对的。公理由谁提供、如何修正，成为下一步要检验的问题（M2）。

## G3 发现被隐藏的结构（2026-10-21；结果见预注册 §G3-M2）

- **区分实验。** 每当 `go to r` 无效，B 先 `examine r`（只在 r 处成功，事先在已用过的局上核对：在 r 处 6/6，不在 r 处 0/78），再重试。11 次全部支持 H_co，对称性检验 9/9 一致。L_co 被采纳，证据等级 [E]。
- **构造的改变。** L_co 改变了信念更新（`go to r` 无效时以 `examine r` 的结果作为到达），监控不再在同址处弃权。评测 60 局：G3-L 修复了 G2A-1 的 15 个失败局，没有破坏任何一局，成功率 0.583 → 0.833。
- **出乎意料的部分。** 只在达成器结束时检查后置条件（G3-S），与完全不检查的 B1 逐局相同。六个分支的沉默失败全部为 0。在 ALFWorld 中，失败本来就是显式的（步数或搜索用尽），监控没有用武之地。
- **理论含义。** 两种解释都足以恢复成功率。合同与监控在这里带来的不是更高的可靠性，而是一个要求：公理必须正确。"发现"的作用是把错误的公理换成正确的规律，使带监控的控制器追平不带监控的基线，而不是超过它。
- **先验的价值。** 位置先验 P_loc 只来自 20 个发现局的计数，就使平均步数减少 30 %（26.0 → 18.1），并多赢 3 局。B2 以 7.3 步、12/12 仍然最好；它的先验来自预训练，规模大得多。
- **被修正的测量。** 冒烟测试中发现 G3 初版在找灯时会打开容器（G2 不会），在正式运行之前改回，只让 L_co 成为差别。
- **一处测量交互（POST-HOC）。** 裁判在成功后对一切动作回复"Nothing happens."。这一屏蔽在一局中被字面监控读成 L_co 的矛盾，使代理在已经成功的局里弃权。
