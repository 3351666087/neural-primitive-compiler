# Mission 06 结果

所有预测都在代码与结果之前锁定，见 `EXPERIMENT_PRE_REGISTRATION.md`。每张表给出锁定判定；POST-HOC 诊断单列，不改变判定。原始数据与评分脚本的位置写在每节开头。区间是 95 % 区间：单个比率用 Wilson 区间，配对差用 10,000 次自助法（种子 70）。

## 1. Gate 0：Mission 05 的可信基

数据：`experiments/g0/`，报告：`M05_TRUST_BOUNDARY.md`、`COMPILER_THEOREM.md`。

| 问题 | 结果 | 证据等级的变化 |
|---|---|---|
| Mission 05 构造器读到的"真值"从哪里来 | 只有 `applicability_cex` 一项，来自构造器自己的宏模型在 N ≤ 7 上的穷举，与裁判无关 | 循环依赖的实质是证据等级，不是信息泄露 |
| 适用性能否不读真值而证明 | APP-R（计数松弛 + Z3）证明了 217 个审计实例中全部 122 个真值适用的实例，0 个错误证明；N = 8..12 上 3,050,000 个随机合格状态中没有反例 | [M]（N ≤ 7）→ [P]（相对于手写编码） |
| 剥离真值后构造是否改变 | A++r 与 A++ 在每个集合、每条路线上构造的计划完全相同；去掉适用性证据则产生 53 个失败的控制器 | 适用性证据是承重的 |
| CIR → 网络 | T-K 定理：类 C_K 上编译保持语义（手证 + 8 条 Z3 引理 + 逐网络前提检查）；1,824 个网络全部通过检查 | [E] → [P]（限 C_K） |
| 规模之外 | N = 20 与分布外的 N = 9、12 上共 63,300 个回合全部成功 | [E] |

被证伪的预测：G0-M1（测量工具要求完整序列相等，双方都循环时被截断在不同长度；POST-HOC 真正的不一致为 0）与 G0-B（CPU 超出预算）。

**Gate 0 的结论。** Mission 05 在它自己的 LINE / ACH-DSL 中是可以去掉循环依赖的，但可信基并没有变小：手写的松弛编码与 Z3 编码，与宏模型的一致性只有经验支持。这一切对外部环境没有任何含义。

## 4. Gate 3：发现被隐藏的结构（M2）

数据：`experiments/g3/`。

### 4.1 B 的主动发现（20 个发现局，456 步）

`go to r` 无效时，B 先 `examine r`（事先核对：只在代理位于 r 时成功，在 r 处 6/6，不在 r 处 0/78），再重试 `go to r`；另做对称性检验。

| 竞争假说 | 预测 | 观察 |
|---|---|---|
| H_co：已在 r 的位置 | examine 成功，重试无效 | examine 11/11 成功，重试 11/11 无效 |
| H_un：不可达 | examine 失败 | 0 次 |
| H_noise：随机失败 | 重试可能成功 | 0 次 |
| 对称性：r 与 r0 同址 | 从别处到达 r 后，`go to r0` 无效 | 9/9 |

矛盾 0，B 采纳 L_co [E]。同时从观察中统计位置先验 P_loc（53 种物体类型，391 次目击）。

### 4.2 评测（60 个新训练局）

| 分支 | 成功 | 沉默失败 | 平均步数 |
|---|---|---|---|
| G2A-1（G2 原样） | 35/60（0.583） | 0 | 17.5 |
| B1（HTN，无监控） | 51/60（0.850） | 0 | 25.4 |
| G3-L：G2A-1 + L_co | 50/60（0.833） | 0 | 26.0 |

| G3-LP：G3-L + P_loc | 53/60（0.883） | 0 | 18.1 |

锁定的 G3-a..G3-f 全部成立。

- L_co 修复了 G2A-1 的 15 个失败局，没有破坏任何一局。
- 但 G3-S 与 B1 逐局相同：后置条件监控在 60 局中一次也没有触发。六个分支的沉默失败全部为 0。按事先写定的解释，这是"两种解释都足够"：在 ALFWorld 的原始条件下，失败本来就是显式的（步数或搜索用尽），中间检测没有用武之地。
- P_loc 使平均步数减少 30 %，并多赢 3 局（都是 G3-L 用尽步数的局）。
- POST-HOC：评测中唯一一次 L_co"矛盾"来自裁判在成功之后对一切动作回复"Nothing happens."，环境本身没有反例。

| 分支 | 成功（95 % 区间） | 沉默失败 | 平均步数 |
|---|---|---|---|
| G2A-1：公理合同 + 字面监控 | 123/134 = 0.918（0.859–0.954） | 0 | 14.2 |
| B1：HTN，无监控 | 132/134 = 0.985（0.947–0.996） | 0 | 15.8 |

| G3-LPR：+ 恢复 | 133/134 = 0.993（0.959–0.999） | 0 | 12.4 |
| B1-LPR：同知识的经典 HTN（L_co、P_loc、恢复，无监控） | 133/134 = 0.993（0.959–0.999） | 0 | 12.5 |
| B2：Opus 5.5 子 agent（60 局子集） | 60/60 | 0 | 8.7 |

- L_co 相对 G2A-1：+0.067（区间 +0.030 到 +0.112，McNemar p = 0.004，9 : 0）。持出房间中同址失败较少（G2A-1 的 11 个失败全部是同址处的弃权），L_co 修复了其中全部 9 个可修复的。

- 持出房间比开发局容易：B1 从 0.850（开发）升到 0.985。

### 5.2 非确定执行（pert：操作以 0.2 的概率无效）

| 分支 | 成功（95 % 区间） | 沉默失败 | "完成"声明的精度 |
|---|---|---|---|
| G2A-1 | 39/134 = 0.291（0.221–0.373） | 0 | 1.00 |
| B1 | 73/134 = 0.545（0.460–0.627） | **56** | 0.57 |
| G3-L | 40/134 = 0.299（0.228–0.381） | 0 | 1.00 |
| G3-S（只查后置条件） | 79/134 = 0.590（0.505–0.669） | 0 | 1.00 |
| G3-LP | 49/134 = 0.366（0.289–0.450） | 0 | 1.00 |
| G3-LPR | 125/134 = 0.933（0.877–0.964） | 0 | 1.00 |
| B1-LPR | 128/134 = 0.955（0.906–0.979） | **5** | 0.96 |
| B2（24 局子集） | 24/24 | 0 | 1.00 |

- 没有监控、没有恢复时，扰动造成 42 % 的局"声称完成却失败"。任何形式的监控（字面或后置条件）都把它们变成弃权。
- 恢复（重发）是成功率的主要来源：G3-LPR 比 G3-LP 高 0.567（区间 +0.485 到 +0.649）。
- 同样的知识与恢复下，合同加监控的控制器与经典 HTN 的成功率相差 −0.022（区间 −0.052 到 0，p = 0.25）。差别在可靠性：前者 0 个沉默失败，后者 5 个。这 5 局都是某个操作连续 3 次被扰动、重发用尽之后，HTN 照常继续并声称完成。监控在同样的 5 局中弃权，另外在 3 局中弃权而 HTN 继续下去成功了。

### 5.3 B2 与成本

- B2 在两个子集上都是全胜（clean 60/60，pert 24/24），步数少于构造器（clean 8.7 对 G3-LPR 的 12.8）。它不需要设计者写的适配器，并能自行处理扰动。
- 代价：clean 每局约 21,400 tokens，pert 每局约 23,500 tokens，Gate 4 合计 1,849,568 tokens。构造器每局的边际代价是 0 tokens 与约 1.4 s CPU（含环境）。它的固定代价是 543 行设计者代码与 456 步发现交互；设计者代码的编写成本（会话 token 与时间）没有单独计量，记为 UNKNOWN。
- 摊销：构造器的固定代价 D 与 B2 每局约 2.1 × 10⁴ tokens 相等时交叉，即 k* ≈ D / (2.1 × 10⁴ tokens)。D 未知，所以交叉点未知。
