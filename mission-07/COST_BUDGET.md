# Mission 07 成本预算与停止规则

本机：Apple M4 MacBook Air（arm64，10 核，CPU），单用户。预算是硬上限；超过时停止并记 RESOURCE_LIMIT，保存部分结果。

## 1. 计算

| 阶段 | 本机 CPU 上限 | 说明 |
|---|---|---|
| Gate 1（已用） | < 0.2 h | 安装与预检 |
| Gate 2：基线与伪造方式 | 10 h | ECO 每次运行 60,000 步，环境本身约 2 秒；开销主要在智能体（结构归纳、规划） |
| Gate 3：候选与消融（开发） | 15 h | 至多 6 次候选修订 |
| Gate 4：确认（α 确认、β、γ、Craftax、果蝇变体） | 15 h | 每个（种子, 分支）一次 |
| 合计 | ≤ 40 h | 墙钟可以并行（至多 8 个进程） |

- 内存：每个进程 ≤ 2 GB。
- 单次运行的墙钟超过 30 分钟即中止并记录，不重跑同一配置（除非修复的是与结果无关的程序错误，并在日志中写明）。

## 2. 模型调用

| 用途 | 上限 |
|---|---|
| B6（LLM 目标提出者，ECO-α 3 个开发种子） | 1,500,000 tokens |
| 留出族作者（隔离会话） | 不由本会话控制；只记录其报告 |
| 其余 | 0：任何智能体分支都不调用 LLM |

## 3. 停止规则

1. **伪造方式**：若 Gate 2 中任何一种伪造方式通过判据，停止，先修订判据。
2. **候选开发**：若 6 次修订后候选在开发种子上仍没有一次完整的 L3，停止开发，按冻结的协议照常运行确认（预期 H2 NOT_SUPPORTED），不再追加修订。
3. **资源**：任何阶段超过上表即停止并记 RESOURCE_LIMIT。
4. **外部生态**：若 Craftax 的底层（感知、位姿、执行器）在开发键上无法让 B1 平均存活超过随机策略，外部迁移记为 INCONCLUSIVE，不替换为自写网格。

## 4. 记账

每次运行记录：环境步数、CPU 秒、峰值内存、结构数、目标数；设计者工作以代码行数与提交记录计；预训练知识记为 UNKNOWN。固定成本（底层与元语言的编写）与边际成本（每个种子的运行）分开报告。
